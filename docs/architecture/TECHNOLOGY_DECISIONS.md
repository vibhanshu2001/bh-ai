# Technology decisions and research record

Reviewed 2026-11-14 using primary project/platform documentation. Recommendations are design decisions; no dependencies were installed, no app was initialized, and compatibility was not runtime-tested. Exact versions must be locked together in the first approved implementation phase. Branch manifests and moving documentation are evidence of current project shape, **not proof that a version is published, stable, vulnerability-free, or compatible with Bhai**.

Review status: core architecture conditionally approved; revised defaults still require product acceptance. [ARCHITECTURE_REVIEW_ACTIONS.md](../planning/ARCHITECTURE_REVIEW_ACTIONS.md) defines reproducible E01–E07 experiments, per-cell evidence and fallbacks. All are not-run; a compatible signature/ABI/native-load path must be demonstrated before P1. Native helper operations remain a minimal candidate justified capability by capability; no helper framework or process adoption system is mandated.

## Recommended stack

Electron on a supported stable line; React 19 stable; TypeScript strict mode; Electron Forge with the documented Webpack integration; Zod 4; SQLite through better-sqlite3 in the utility process; Fuse.js stable 7.x and Compromise tokenizer; selected systeminformation APIs behind bounded adapters; Node built-ins for subprocess/files/network; on-demand signed Swift AppKit/CoreAudio helper. Vitest, React Testing Library and Playwright provide tests. No web backend, ORM, NLP classifier, AI SDK, or extra state/workflow framework is required.

## Decision matrix

All runtime components below operate locally/offline. Network checks and opening saved web pages are explicitly requested network operations; they are not a cloud dependency. Build tooling may download packages/headers during development, not on the user's first launch. License labels describe upstream projects/observed manifests; audit the exact selected artifacts and transitive notices before release.

## Verified compatibility facts and limits

1. Electron supports the latest three stable majors; choose the current patched stable, then validate against selected macOS deployment target. No exact Electron major is frozen by this plan. [Electron support policy](https://www.electronjs.org/docs/latest/tutorial/electron-timelines).
2. React's official version page currently lists 19.3. Treat 19.x stable as a recommendation; verify all peer dependencies at lock time. [React versions](https://react.dev/versions).
3. Zod's current docs target TypeScript ≥5.5 with strict mode and provide JSON Schema conversion. Select an actively maintained TS release satisfying all build tools. [Zod requirements](https://zod.dev/).
4. Forge's Vite plugin remains explicitly experimental in the documentation inspected. Choose Forge's Webpack plugin for this design; benchmark its production output, not dev build speed. [Forge Vite status](https://www.electronforge.io/config/plugins/vite), [Webpack integration](https://www.electronforge.io/config/plugins/webpack).
5. The observed better-sqlite3 branch manifest reports 13.2.0, Node ≥22, and Darwin arm64/x64 entries. This is a moving branch observation, not a release guarantee. Select a published compatible version and prove native loading in the signed **utility process**, including unpacked native assets. [Binding manifest](https://raw.githubusercontent.com/WiseLibs/better-sqlite3/master/package.json). Electron warns that native modules can require rebuilding for its ABI; Forge integrates rebuilding. [Electron native modules](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules).
6. Compromise's observed branch is 14.20.0 with typed tokenizer exports and Node ≥18; no ABI dependency is apparent from the tokenizer contract. Actual bundle imports must be checked because full exports can pull extra language data. [Manifest](https://raw.githubusercontent.com/spencermountain/compromise/master/package.json).
7. Fuse's observed branch is 7.6.0-beta.0 with Apache-2.0 licensing and ESM/CJS typed exports. Do **not** automatically adopt the beta or assume historical MIT terms cover it. Prefer a published stable 7.x with exact license/NOTICE review. [Manifest](https://raw.githubusercontent.com/krisk/Fuse/main/package.json), [release history](https://github.com/krisk/Fuse/releases).
8. systeminformation's observed manifest reports 5.33.19, MIT, CommonJS with types and Darwin support. Project activity lists multiple recent feature increments. Not every field/function works on macOS or can be aborted; capability tests and wrapper deadlines are required. [Manifest](https://raw.githubusercontent.com/sebhildebrandt/systeminformation/master/package.json), [project changelog](https://github.com/sebhildebrandt/systeminformation#news-and-changes).
9. Playwright labels Electron automation experimental. It is appropriate for smoke tests but cannot validate real menu-bar hit testing, TCC, notarization, MDM or all global shortcut behavior alone. [Playwright Electron API](https://playwright.dev/docs/api/class-electron). Vitest and Testing Library are active documented tools, but this task did not run them. [Vitest guide](https://vitest.dev/guide/), [Testing Library](https://testing-library.com/docs/react-testing-library/intro/).

## NLP alternatives and maintenance assessment

Fuse and Compromise have visible release histories, typed exports and bounded primitives directly matching the task. This is evidence of usable ecosystems, not a support SLA. Their maintainers remain external dependencies, so keep adapters replaceable and exact version updates covered by corpus/performance tests. No numerical popularity rank is treated as a substitute for correctness.

Natural's observed manifest reports 8.2.6 and MIT with an extensive set of NLP and database-related transitive dependencies. It remains a relevant established library, but a full import is poor value for Bhai's small vocabulary; importing internal tokenizers risks unsupported subpaths. [Natural manifest](https://github.com/NaturalNode/natural/blob/master/package.json), [releases](https://github.com/NaturalNode/natural/releases). Compromise is a narrower fit with an explicit tokenizer export.

wink-nlp documents tokenization and linguistic processing with a separate English model; the inspected release history includes 2.4.0 and later fixes. It is a credible maintained alternative, but benchmark claims concern its own corpus/hardware and do not establish Bhai's accuracy/memory. Its MIT library/model artifacts require exact artifact license checks. [wink source](https://github.com/winkjs/wink-nlp), [release history](https://github.com/winkjs/wink-nlp/releases). NLP.js is a capable broader bot/intent framework under MIT; training-based classification adds opaque confidence and data requirements outside the selected deterministic non-AI design. [NLP.js source](https://github.com/axa-group/nlp.js).

Neither English NLP quality nor a multilingual package label demonstrates Roman Hinglish negation or project-name handling. The chosen finite grammar remains necessary application behavior; see [LANGUAGE_ENGINE.md](LANGUAGE_ENGINE.md) for the safety model and confidence tiers.

## Version and license gate for implementation

Before installing in a future approved phase, record: exact published version, registry integrity hash, release date, Node engines, ESM/CJS exports, types/peer dependencies, Electron embedded Node version, supported macOS/architectures, native rebuild method, selected artifact license/NOTICE, advisories and dependency tree. Create a lockfile only then. Recheck moving sources; do not pin a branch commit merely because this document observed it.

Phase-zero compatibility smoke: packaged/signed tray → renderer → preload → main → utility → SQLite write/read; native helper app status + volume capability; process-group cancellation; tokenizer and Fuse imports in release bundle. Pass on each promised architecture/OS. Native ABI/load/signing failure is an architecture blocker before building the full feature catalog; node:sqlite can be reconsidered behind the repository interface if its chosen embedded-Node status and packaging are demonstrably better.

The smoke description is expanded by P0 E01 (signed utility/storage and crash consistency), E02 (native assets/signatures/fuses/notarization), E03 (AppKit/CoreAudio necessity and refusal), E04 (actual Terminal cwd/VS Code workspace), E05 (foreground groups/cancel/crash gaps), E06 (signed denied-access profiles), and E07 (imports and real-phrase collection readiness). Use the selected lock/runtime, installed Finder-launched build and controlled fixtures; a development launch, mock, ad-hoc signature or documentation citation cannot pass those gates. Fallbacks require executed evidence and acceptance, not silent sandbox/entitlement relaxation.

Review-stage simplifications do not change the stack: single active workflow/FIFO initially, phase-sized SQL migrations, one narrow on-demand helper only where proven necessary, and interrupted/unknown observation-based recovery. Increasing workflow concurrency or adding process adoption requires measured need and new tests, not new baseline dependencies. See the [incremental complexity plan](../planning/ARCHITECTURE_REVIEW_ACTIONS.md#incremental-complexity-decisions).

## Deliberate omissions

No Temporal/BullMQ/Redis server, general state-machine runtime, graph layout dependency, vector database, cloud telemetry backend, shell-profile auto-loader, node-pty, AI adapter implementation, model/classifier dependency, auto-update infrastructure or continuously running monitor. The workflow state machine and phrase tables are small domain code with existing validation/storage primitives, not general infrastructure to be built from scratch.
